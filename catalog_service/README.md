# Служба каталога шаблонов (`catalog_service`)

Рабочее место владельца и витрина над каталогом шаблонов (`catalog/`).
Пять экранов интерфейса (`catalog-ui/`) и три осознанных действия:
сохранить черновик, собрать черновик, выпустить версию.

Каталог — версионируемый пакет данных с отпечатком, а не живая база.
Поэтому правки копятся ЧЕРНОВИКАМИ вне пакета (в рабочей папке службы), в
пакет они попадают одним действием «Собрать черновик», а имя версии даёт
только владелец действием «Выпустить версию».

## Назначение

| Что | Где живёт |
|---|---|
| данные каталога | `catalog/` в репозитории (шесть файлов читателя, `transition/`, `schema/`, `releases/`) |
| черновики и журнал действий | `<CATALOG_WORK_DIR>` — вне репозитория (умолчание `<корень данных>/catalog-work`) |
| замок папки каталога | временная папка машины, `cosmos-catalog-<хеш пути>.lock` |
| интерфейс | `catalog-ui/dist` (собранная статика коммитится: установка не требует Node) |

Служба ничего не разбирает сама: чтение — `template_catalog`, запись —
`template_catalog.writer`, «что изменилось» — `template_catalog.diff`,
состояния исполнителей — `template_catalog.bindings.best_states` (тот же
закон, что у двери COSMOS и у экрана базы шаблонов).

## Запуск

```
# рабочее место владельца
.venv\Scripts\python.exe -m catalog_service --port 8105 --actor owner

# витрина (площадки, установка заказчика) — ни одной записи на диск
.venv\Scripts\python.exe -m catalog_service --port 8105 --read-only

# приём очереди заявок, принесённой с площадки (шаг 6)
.venv\Scripts\python.exe -m catalog_service import-requests --inbox <папка> --reply
```

Умолчание `--host 127.0.0.1`: входа и паролей у службы нет, публикуемое
умолчание обязано быть безопасным; наружу площадки отдают службу
туннелем, а не открытым портом. Для доверенной сети — явно `0.0.0.0`.

Ключи: `--port` (8105), `--host`, `--actor owner|analyst`, `--read-only`,
`--catalog <папка>`, `--work-dir <папка>`. Ключ сильнее переменной среды;
переменные и умолчания — в `API-CONTRACT.md` §1.

## Режимы и роли

| Режим | Когда | Что можно |
|---|---|---|
| просмотр | роль не задана либо `--read-only` | все ручки чтения; ни замка, ни журнала, ни рабочей папки |
| правка, аналитик | `--actor analyst` | черновики (кроме смены `status`), подача заявок, сборка |
| правка, владелец | `--actor owner` | всё: решения по заявкам, снятие записей, выпуск, загрузка |

Слово владельца 06.09.2026: «заявки принимает и версии выпускает только
владелец». Недоступные кнопки интерфейс гасит с причиной в подсказке, а
не прячет.

## Точки наблюдения

`GET /healthz` (жив; диска не читает), `GET /readyz` (готов: каталог
читается и проходит проверку, рабочая папка доступна), `GET /versionz`
(что развёрнуто: версии службы и читателя, срез кода, версия и отпечаток
каталога). Наружу уходят только состояния, отпечатки и имена файлов
относительно папки каталога — абсолютных путей машины не бывает.

## Как проверить

1. Поднять службу на свободном порту:
   `.venv\Scripts\python.exe -m catalog_service --port 8105 --actor owner`.
   В печати — адрес, папка каталога, версия, отпечаток и рабочее место.
2. `GET http://127.0.0.1:8105/healthz` → `{"status": "ok"}`;
   `GET /readyz` → `ready: true`, `errors: 0`; `GET /versionz` → версия
   каталога и отпечаток.
3. `GET /` → 302 на `/ui/` (если интерфейс собран) либо 503
   `ui-not-built` словами.
4. Сохранить черновик записи (`PUT /api/drafts/families/<id>`) — файл
   появляется в рабочей папке, а отпечаток `catalog/` НЕ меняется.
5. `POST /api/versions/assemble` — версия по правилу, в ответе `derived`
   и цепочка команд: пересчёт посева и дельты (`--refresh`) первой
   строкой, перегенерация привязок, закон паритета последней.
5а. `GET /api/versions/release/checks` — сухой прогон выпуска:
   ДВЕНАДЦАТЬ предпроверок словами (восемь шага 5, три шага 6 —
   кандидаты конвейера, полнота исполнителей, заявки в работе — и
   двенадцатая, паритет с кодом COSMOS), на диск не ложится ничего. Тот
   же перечень показывает диалог «Выпустить версию» ДО нажатия.
5в. Двенадцатая строка чек-листа — вердикт закона паритета
   `catalog/tools/parity.py`, которого служба зовёт подпроцессом:
   красный — отказ `parity-red` (подтверждением не снимается);
   «не судился» (закона рядом нет, код 2, предел) и предупреждение
   судьи — отказ `parity-unconfirmed`, снимаемый полем
   `confirm_parity: true` выпуска. Вердикт пишется в журнал выпуска
   словами.
5б. Машинный канал заявок (шаг 6): без `CATALOG_MACHINE_TOKEN` подача
   продукта отказывает словами (403 `machine-channel-off`) — это
   умолчание площадок. С заданным токеном `POST /api/requests` с
   заголовками `X-Catalog-Product` и `X-Catalog-Token` заводит заявку
   (201), повтор той же — 200 «уже подана», а отпечаток каталога не
   меняется: заявки живут вне пакета.
6. После сборки цепочка `next` начинается с
   `build_from_code.py --refresh --out catalog` (посев и дельта — не
   рукопись, а проекция каталога) и кончается `parity.py` → 0 красных.
   Гейты содержания после сборки по построению НЕ краснеют: база
   заморозки — снимок шага 1, рост — вычисленной дельтой (руководство
   13.9 и 13.13). Пересмотр атрибутов базовых записей — новым файлом
   снимка по слову владельца.
7. Погасить службу (Ctrl-C): замок папки каталога отпускается.

Целевые тесты службы:

```
set PYTHONUTF8=1 && .venv\Scripts\python.exe -m pytest -q tests\catalog_service
```

## Файлы

| Модуль | О чём |
|---|---|
| `__main__.py` | разбор ключей, замок, печать при старте, uvicorn |
| `settings.py` | `Settings.from_env(argv)`, формула корня данных, роли и режим |
| `identity.py` | две роли, десять операций записи, тексты отказов |
| `app.py` | `create_app(settings)`, ручки §3 контракта, раздача `/ui/` |
| `store.py` | экземпляр каталога, черновики, сборка в памяти, замки |
| `assemble.py` | «Собрать черновик»: правило версии, запись писателем |
| `request_queue.py` | заявки: подача (экран и машинный канал), закон номера из читателя, решения и пересмотр, ключ CR, кандидат конвейера |
| `import_requests.py` | `import-requests --inbox`: приём очередей заявок с площадок по HTTP; каталог пишет только служба |
| `releases.py` | «Выпустить версию»: двенадцать предпроверок (включая паритет с кодом COSMOS подпроцессом), снимок, git |
| `executors.py` | таблица «запись × вид × продукт», свежесть, предпроверка B01 |
| `markers.py` | перечень маркеров заказчика (ленивый импорт линта) |
| `journal.py` | журнал действий рабочего места |
| `errors.py` | форма отказа: код, слова, перечень проблем |
| `schemas/draft.schema.json` | форма файла черновика |
| `API-CONTRACT.md` | контракт ручек, кодов, переменных и адресов экранов |
