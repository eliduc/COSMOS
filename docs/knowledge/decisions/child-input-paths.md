# Пути входов, уходящие в расчёт

## Контекст

Реестр хранит пути входов **логически** — «final-report/x.json»,
«data/uploads/…». Физически файл лежит либо в корне данных
(`<репозиторий>-data`), либо в самом репозитории; знание об этом держит
`registry.resolve_rel` (пробует корень данных, затем репозиторий — в
этом порядке, потому что одноимённый `final-report` есть и в
репозитории).

Исполнитель задач передавал логическую запись в командную строку как
есть. Дочерний процесс разворачивал её от своего рабочего каталога —
корня репозитория — и на контуре с вынесенными данными файла не
находил. Ростеринг из интерфейса на контуре заказчика умирал через
секунду: «required input does not exist:
final-report\gerad_colgen_selected_….json», хотя каталог существовал, а
его отпечаток, посчитанный тем же родителем через `resolve_rel`, в
команде совпадал с файлом. То есть родитель знал верный путь и всё
равно передавал неверный (найдено владельцем 2026-08-13).

Ветка проверки (`validate`) с самого начала разворачивала пути
правильно — расхождение веток и было дефектом.

## Решение

Ни одна логическая запись не уходит в дочерний процесс: путь
разрешается **там, где известна топология** — в родителе, единой
функцией `_child_path(rel, что)`, применённой ко всем входам всех линий
(построитель цепочек, обе colgen-линии, этап 2, мультироль).

Пропавший вход — отказ на сборке команды, с именем входа и полным
путём (HTTP 400), а не смерть дочернего процесса кодом 2 через
полминуты.

## Следствия

- Гейт в тестах перебирает все команды всех линий и требует, чтобы
  каждый файловый аргумент существовал ровно так, как записан; тест
  печатает число рассмотренных команд и путей.
- Прежний тест, собиравший команду с набором-фантомом, приведён к
  реальным файлам: новый контракт таких входов не пропускает.
- Контур заказчика — единственный, где данные вынесены и репозиторий
  чист, поэтому дефект не проявлялся на площадках разработки.
