# Контуры

## Локальная машина

Место разработки и прогона тестов; приложение постоянно не запущено.
Один репозиторий `crew-demo` и его каталог данных `crew-demo-data`.
Каталогов `cosmos-*` локально нет — контуры живут только на legion.

### Порты служб пакета (после шага 5 каталога шаблонов, 08.09.2026)

Служб три: веб-приложение, панель CDPM и служба каталога шаблонов;
рядом — решатель ростеринга. Номера службы каталога — ряд «+10» к
панели CDPM.

| Площадка | Веб-приложение | Панель CDPM | Решатель | Служба каталога |
|---|---|---|---|---|
| Test (`cosmos-test`) | 8092 | 8095 | 8098 | **8105** |
| Stage (`cosmos-stage`) | 8091 | 8096 | 8100 | **8106** |
| Prod (`crew-demo`) | 8090 | 8097 | 8099 | **8107** |
| Локальная машина | 8123 | 8095 | 9099 | **8105** |
| Установка заказчика | 8090 (8090–8099 без 8095) | 8095 | 9096 | **8105** |

Служба каталога всюду слушает 127.0.0.1; наружу — туннелем. На
площадках и у заказчика она поднимается только в режиме просмотра
(`--read-only`): правки, заявки и выпуск версий — на рабочем месте
владельца. Края: `cosmos-catalog-{test,stage,prod}.fregene.ai` под
существующей маской Access `cosmos-*.fregene.ai` (`cloudflared tunnel
route dns` + ingress в `config.yml`).

### Настройки каталога по контурам (шаг 6, конвейер пополнения)

| Переменная | Рабочее место владельца | Test / Stage / Prod | Установка заказчика |
|---|---|---|---|
| `CATALOG_ACTOR` | `owner` | не задана (просмотр) | не задана |
| `CATALOG_READ_ONLY` | не задана | `1` (пусковик с `--read-only`) | `1` |
| `CATALOG_MACHINE_TOKEN` | задан — машинный канал заявок открыт | НЕ задан | НЕ задан |
| `CREW_CATALOG_API_URL` | `http://127.0.0.1:8105` | `…:8105` / `…:8106` / `…:8107` | не задана |
| `CREW_CATALOG_TOKEN` | равен токену службы | не задан | не задан |
| `CREW_CATALOG_URL` | адрес для ссылок с экранов | адрес края контура | не задана |
| `CREW_CATALOG_OUTBOX` | умолчание (`cosmos-catalog-requests/outbox` в каталоге данных) | умолчание | умолчание |

Значения таблицы задаются ЯВНО: своего умолчания код не подставляет —
незаданный `CREW_CATALOG_API_URL` означает «машинный канал выключен»
(иначе установка на площадке ходила бы на чужой локальный порт при
каждом нажатии). Канал считается настроенным, когда заданы адрес И
токен вместе.

`CATALOG_MACHINE_TOKEN` живёт ТОЛЬКО на рабочем месте владельца: без
него машинный канал заявок отвечает `machine-channel-off` словами, и
это правильное состояние площадки. Заявки, рождённые на площадке,
копятся в очередях продуктов под каталогом данных
(`cosmos-catalog-requests/outbox` у COSMOS, своя папка у CDPM);
перенос — копией папок, приём на рабочем месте —
`python -m catalog_service import-requests --inbox <папка> --reply`,
файлы-ответы возвращаются той же копией.

Чек-лист раската каталога (сверх общего): очереди заявок продуктов
перенесены и ПУСТЫ перед раскатом; в `catalog/candidates/` кандидатов
нет (кандидат — черновик конвейера, в поставку он не входит); версия
и первые 12 знаков отпечатка каталога на всех площадках равны между
собой и равны голове раската.

Каталог данных выводится из имени репозитория: `cosmos-<метка>` →
`cosmos-<метка>-data`. Контур заказчика — полноценное приложение COSMOS
**без** `COSMOS_PROD_DIR`/`COSMOS_STAGE_DIR` и без очередей
самоулучшения: площадка заказчика не управляет чужими контурами и не
несёт конвейер разработки.

Домены заказчиков за Cloudflare Access: у self-hosted-приложения
максимум пять destinations, поэтому контуры заказчиков покрыты одной
маской `cosmos-*.fregene.ai` (введена 2026-08-14 вместо точечной
по-контурной) — новый контур требует только DNS-маршрут
(`cloudflared tunnel route dns`) и ingress в `config.yml`, шага в
панели Access больше нет. Заголовок приложения контура помечается
переменной `CREW_CONTOUR_LABEL` (суффикс «/<метка>» во вкладке и
шапке, переживает смену языка; см. руководство, часть 1 §4).
Задача планировщика каждого контура заказчика — автозапуск
при загрузке; сторож Cosmos-Watchdog контуры заказчиков не ведёт.

## Грабли раската (проверены 2026-08-11 на контуре заказчика)

- **`core.autocrlf=true` на legion меняет байты при выкладке.** Файлы,
  попавшие на площадку через `scp` с однобайтовыми переводами строк,
  после `git merge` получают двухбайтовые: 7 из 10 контрольных файлов
  «расходятся» по SHA-256 при полностью одинаковом содержимом. Сверка
  обязана сравнивать текст с нормализованными переводами строк.
- **Неотслеживаемые файлы, которые коммит добавляет, блокируют `ff`.**
  Порядок: копия → удаление → `checkout -- .` → `merge --ff-only` →
  сверка восстановленного с копией.
- **`origin` контура заказчика смотрит на `cosmos-test` на самом legion**, а не
  на локальную машину; объекты доставляются только бандлом.
- Верификация, которая что-то доказывает: HEAD равен целевому коммиту,
  дерево чистое, `/api/instances` без пропуска = 401, и прикладной гейт
  (для контура заказчика — `pairing_audit.py` на принятом каталоге).
