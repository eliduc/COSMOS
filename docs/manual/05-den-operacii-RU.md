## 1. О чём эта часть

Страница «Оптимизация» → «Операция» сопоставляет плановое расписание с фактом дня операции: пунктуальность, выполнимость рейсов, задержки по причинам. Отсюда же отклонения превращаются в события режима «Сбой» ([Часть 6](06-sboj-i-remont-RU.md)), а исторический факт используется для сравнения «наш ростер против исторического».

Из описания экрана: «Факт можно импортировать из публичных данных BTS (реальный день) или вводить вручную. Ползунок времени показывает, что „уже случилось“ к выбранному часу. Кнопка „Сгенерировать события Сбоя“ превращает отклонения в события режима „Сбой“, после чего доступна пересборка окрестности.»

| Действие | Кто выполняет | Кто утверждает |

| Отчёт сравнения ростеров | Планировщик | Диагностическое сравнение обсуждают стороны приёмки (документ не юридический) |

## 3. Журнал фактов и конвенция «нет факта = по плану»

Факт хранится как **журнал событий по рейсам**: задержка вылета/прилёта (в минутах), отмена, диверсия (посадка не в плановом аэропорту), причина (классификация задержек по категориям BTS — перевозчик, погода, национальная система, безопасность, поздний борт).

Ключевая конвенция: **отсутствие факта по рейсу означает «выполнен по плану»**. Поэтому таблица всегда показывает все рейсы дня: у одних статус из факта, у остальных — плановый.

### 3.1 Ключи фактов

Факт адресуется рейсу одним из трёх ключей — от простого к точному:

| Ключ | Пример | Когда достаточен |
|---|---|---|
| номер | `F100` | Номер летает в наборе один раз |
| номер@день | `F100@2026-03-02` | Номер летает несколько раз, но в сутки — один |
| номер@день-время | `F100@2026-03-02T09:00` | Несколько вылетов одного номера в сутки |

Правила разрешения: неоднозначный ключ отклоняется с диагностикой («номер летает несколько раз — укажите дату», «несколько вылетов в эти сутки — укажите время»). Если два вхождения одного номера вылетают в одну и ту же минуту, ключ `номер@день-время` перестаёт различать их. С 2026-07-20 такой факт **неадресуем полностью**: генерация событий «Сбоя» пропускает эти рейсы со счётчиком, а ручной ввод факта по такому ключу ОТКЛОНЯЕТСЯ с ошибкой «several departures in the same minute». Легаси-факты, записанные под коллизионным ключом раньше, на строки плана-факта больше не ложатся — они видны строкой «Фактов проигнорировано — рейс не адресуем (несколько вылетов в одну минуту): N» над таблицей и удаляемы обычным DELETE с указанием дня-времени.

С 2026-07-20 каждая строка плана-факта несёт **сам ключ факта** и **адрес вхождения рейса**. Это сделано ради других частей системы: без них любой следующий потребитель (первым в очереди — контур «Буфер стыковки», [Часть 7](07-samousovershenstvovanie-RU.md)) заново реализовывал бы то же трёхуровневое правило адресации, а вторая реализация неизбежно разошлась бы с первой. Пустой ключ означает **«адресовать невозможно»** — и это не то же самое, что «факта нет»: рейс с пустым ключом надо исключать из расчётов, а не считать выполненным по плану.

## 4. Импорт факта из BTS **[Планировщик]**

BTS (Bureau of Transportation Statistics — публичная статистика фактических полётов США) — источник реального операционного дня для демонстраций и теневых прогонов.

1. Выберите «Экземпляр».
2. Нажмите «Импорт факта (BTS)». Система подберёт дату с максимальным числом совпадений рейсов экземпляра с историческими данными и загрузит задержки/отмены/причины.
3. Импорт доступен только для экземпляров, построенных из данных BTS (`source=bts`); для прочих отклоняется. Импорт перезаписывает факты по совпавшим рейсам поверх текущего журнала — в том числе ручные записи (источник помечается в поле `note` — примечании каждого факта).
4. «Сбросить факт» очищает журнал фактов экземпляра.

## 5. KPI и срез по времени

Плитки KPI (key performance indicators — ключевые показатели) над таблицей:

- **Выполнимость** (completion) — доля выполненных рейсов (не отменённых);
- **OTP вылет / OTP прилёт** (On-Time Performance) — доля рейсов, отклонение которых не превышает 15 минут;
- **Покрытие фактом** — доля рейсов, по которым есть факт; при нуле отчитавшихся показатели честно показывают прочерк «—», а не 100 %.

Ползунок «Срез на время дня»: таблица показывает состояние «что уже случилось» к выбранному часу (шаг 15 минут). Примечание интерфейса: «Плитки — итог за сутки; таблица ниже — срез на выбранное время.» Колонки таблицы: «Рейс / Маршрут / План. вылет (UTC) / Статус / Δ вылет / Δ прилёт / Причина». UTC — всемирное координированное время.

## 6. Генерация событий «Сбоя» из фактов **[Планировщик]**

Кнопка «Сгенерировать события Сбоя» переводит отклонения факта в операционные события режима «Сбой»:

- отменённый по факту рейс → событие «Отмена рейсов»;
- задержка вылета строго больше порога → событие «Сдвиг рейсов» на фактическую величину; задержка ровно в порог (по умолчанию 15 минут) считается «вовремя» и события не создаёт;
- события адресуются **конкретному вхождению** рейса: при повторных номерах используется адрес вхождения (`flightLegId`); факты, которые нельзя однозначно привязать к вхождению, пропускаются и подсчитываются отдельно (счётчик неадресуемых в итоге операции);
- генерация идемпотентна: повторное нажатие не плодит дубликаты событий.

После генерации переходите на «Доску» → кнопка «Сбой…» — там события видны и доступен ремонт ([Часть 6](06-sboj-i-remont-RU.md)).

## 7. Сравнение ростеров (историческая репликация)

Блок «Сравнение ростеров (историческая репликация)» на странице «Операция». Из описания: «Наш ростер (вторая стадия + правки доски) против исторического (назначения из flightAssignments загруженного набора): покрытие, блок- и кредит-часы, оплачиваемые часы, стоимость, нарушения.» («Вторая стадия» в тексте экрана — это этап 2.)

1. «Построить отчёт» — таблица сравнения по показателям: наш ростер против исторических назначений (поле `employee` в `flightAssignments`, см. [Часть 2](02-podgotovka-dannyh-RU.md)).
2. «Скачать сравнение (MD)» — диагностическое сравнение (документ Markdown): покрытие, часы, стоимость и нарушения по правилам доски. Документ не заверяет полную легальность ростера (ролевая легальность мест не сертифицируется) и не является юридическим актом приёмки — соответствующий дисклеймер содержится в самом документе.

Отчёт диагностический: сравнение честно оговаривает, что исторический ростер мог решать другую задачу (другие правила, другой парк), поэтому разница трактуется как ориентир, а не приговор.

## 8. Частые ошибки и что они означают

| Симптом | Причина | Действие |
|---|---|---|
| «Выберите экземпляр.» в таблице | Экземпляр не выбран | Выберите в списке «Экземпляр» |
| Ошибка ключа: «номер летает несколько раз — укажите дату» | Ключ факта неоднозначен | Используйте `номер@день` или `номер@день-время` (раздел 3.1) |
| Импорт BTS отклонён | Экземпляр не построен из данных BTS, либо параллельный импорт уже выполняется | Импорт доступен только для BTS-экземпляров; дождитесь завершения параллельного импорта |
| OTP показывает «—» | Ни один рейс не отчитался | Это честное «нет данных», а не ноль |
| Часть фактов не стала событиями Сбоя | Факты неадресуемы (нельзя привязать к конкретному вхождению) | Смотрите счётчик пропущенных; при необходимости заведите событие вручную с точным адресом |
| Повторное нажатие «Сгенерировать события Сбоя» ничего не добавило | Идемпотентность: события уже созданы | Это норма |

## 9. Как проверить

1. Выберите экземпляр с посчитанным ростером и нажмите «Импорт факта (BTS)». Ожидаемо: сообщение об импорте с числом сопоставленных рейсов; плитки Выполнимость/OTP заполнились; в таблице появились статусы, задержки и причины.
2. Сдвиньте ползунок «Срез на время дня» на середину дня. Ожидаемо: рейсы после выбранного часа исчезли из таблицы (она показывает только уже вылетевшие к выбранному времени), плитки не изменились (они за сутки).
3. Нажмите «Сгенерировать события Сбоя». Ожидаемо: отчёт о числе созданных событий (отмены и сдвиги больше порога); повторное нажатие дубликатов не создаёт.
4. Откройте «Доска» → «Сбой…». Ожидаемо: сгенерированные события в списке, у повторных номеров указано конкретное вхождение («номер · дата время»).
5. Нажмите «Построить отчёт» в блоке сравнения ростеров. Ожидаемо: таблица «наш против исторического» по покрытию, часам и стоимости; «Скачать сравнение (MD)» отдаёт документ.
