COSMOS — конвейер пейринг–ростеринг

Конвейер COSMOS

Как читать эту схему

Блоки — этапы конвейера от постановки (ВМП) до решений по пейрингу и ростерингу. Активный этап пульсирует, на блоке — живые параметры хода (включая процент близости к оптимуму). Блок «Эскалация» связан с пулом возвратной стрелкой: непокрытые рейсы ступенями усиливают перебор до развязки — покрыт либо невозможность доказана. Щелчок по блоку открывает его рабочий экран.

Прогоны

Расчёт по пакету постановки: приём → пейринг → проверки → ростеринг → проверки → выгрузка

Что такое прогон

Прогон — запись о расчёте по пакету постановки из CDPM: текущий прогон принимает пакет (каналом или загрузкой), хранит все попытки пейринга и ростеринга с проверками по ВМП и ИДАК и паспорт — чем и на чём считалось. Новый пакет в текущий прогон не стирает прежний: он остаётся в истории прогона вместе со своими попытками. Любую завершённую попытку можно повторить из журнала (байт в байт) или заново.

Удаление переносит папку прогона в архив площадки (каталог cosmos-runs-archive рядом с прогонами) — вернуть можно переносом папки обратно; номера удалённых прогонов заново не выдаются.

Правила набора

Зона 1 — импорт данных задачи

Рейсы, экипажи, допуски, недоступности — всё, что описывает саму задачу планирования. Итог каждого пути — канонический экземпляр в реестре.

Загрузка нового экземпляра

Канонический формат (слой 1) — см. вкладку «Формат и правила». Можно выбрать файл .json или вставить JSON в поле ниже.

Импорт SSIM

Как работает этот экран

Импорт расписания в формате IATA SSIM (глава 7, записи типа 3). SSIM не содержит экипажей, поэтому базы экипажей задаются вручную. Диапазон дат — необязателен (по умолчанию весь период файла).

—

Импорт из «Меридиана»

Как работает этот экран

Импорт выгрузки системы «Меридиан» (постановка задачи ростеринга: рейсы, экипажи, допуски, наземные активности). Конвертация детерминированная, без ИИ — данные не покидают сервер. Файл решения солвера — необязательный справочник типов воздушных судов и географии. Персональные данные (ФИО, даты рождения) отбрасываются при конвертации. Диапазон дат — по умолчанию плановое окно файла.

—

Нужна построителю цепочек для уровней свободы 1 и 2 — сравнить «как есть» с перестроенным вариантом.

Импорт из произвольных файлов

Как работает этот экран

Загрузите один или несколько файлов (CSV, Excel, JSON или текст) — например, рейсы и экипажи по отдельности. Если формат не наш, модель ИИ предложит соответствие полей; данные проверяются, а сохранение — после вашего подтверждения. Модель выбирается по области данных набора.

Дельта-обновления (эксплуатация)

Как работает этот экран

Регулярные изменения без повторного полного импорта: сообщения об изменении расписания (поддержанное подмножество ASM/SSM: NEW, CNL, TIM, EQT) и инкрементальные кадровые выгрузки (CSV с каноническими колонками; диф по табельному, без молчаливых удалений). Сначала предпросмотр, затем применение; повтор той же дельты отклоняется по отпечатку SHA-256; всё пишется в журнал.

Зона 2 — импорт правил

Правила работы экипажей (лимиты, отдых, ограничения) — отдельно от данных задачи. Итог — черновой Пакет правил с происхождением; утверждение — вручную на вкладке «Пакеты правил». Конвертация детерминированная, без ИИ.

Подробнее о форматах
  • Jeppesen Rave — детерминированный разбор ядра языка (правила, параметры, сравнения); всё неразобранное честно считается, семантика не угадывается.
  • Таблица норм — колонки «имя, значение, единица, окно»; канонические имена сразу дают исполняемые правила.
  • XML-контейнер — инвентаризация ограничений смежных областей (графики медсестёр, сменный ростеринг) в записи «ресурса».
  • Файл оптимизатора вендора — параметры и веса правил (как в наборе крупного перевозчика).
  • Выгрузка «Меридиана» — числовые лимиты на сотрудниках и переопределения отдыха.
  • Обменный формат COSMOS — нейтральный JSON, экспортируемый любой стороной без кода.
  • Sabre, NetLine/Crew, AIMS — форматы закрыты; приёмники ждут образцов, разбор по догадкам не выполняется.

Мультироль — раздельные ротации ролей

        

        
Сравнение с со-локацией

        
Со-локация — обычный этап 2 (обе роли летят одну ротацию); мультироль — независимые ротации на роль. Пустая колонка = этот режим ещё не запускался.

        

          

            
            
          

        

      


      

        
Стоимость и гостиницы

        

          Оценка по ставкам из «Формат и правила»: оплата за блок-часы,
          суточные за время вне базы, гостиницы за ночёвки по станциям.
          Ночёвки считаются по границам суток UTC (без местных часовых
          поясов); один пейринг = один экипаж. Полная модель оплаты труда
          (гарантии, риги) — в дорожной карте.
        

        

      


      

        
Оплата и кредитные часы (pay-and-credit)

        

          Промышленная модель оплаты: кредит пейринга — максимум из налёта,
          рига служебного времени (1 кредитный час за N часов на службе),
          минимального кредита за служебный период и рига времени вне базы.
          На уровне ростера каждому линейному члену экипажа платится не
          меньше месячной гарантии. Коэффициент «кредит/налёт» — главная
          метрика эффективности: всё сверх 1.00 — «мягкие затраты», которые
          должен убирать оптимизатор. Параметры контракта — в «Формате и
          правилах». Времена — UTC.
        

        

      


      
Визуализация ростера и пейрингов

      
Визуализация появится после расчёта этапа 2.

      


        

          

            
Ростер месяца — экипаж × дни

            

          

          
Строка — член экипажа, столбец — день. Дежурство сплошным, дедхед штриховкой, недоступность и выходные — отдельными состояниями. Справа — блок-часы за период. Наведите на ячейку.

          

          

          

        


        

          
KPI и справедливость нагрузки

          
Распределение блок-часов по экипажу (сортировка по возрастанию; отмечены медиана, минимум и максимум) и удовлетворённость предпочтений — не среднее, а разброс.

          

            

            

          

        


        

          

            
Пейринг — временнáя развёртка дежурств

            

          

          
Рейс — сплошной сегмент, дедхед — штриховка, между дежурствами сит или отдых (пунктир с длительностью и станцией). Ось — UTC. Ниже — пейринг-лист с точными числами.

Схема цепочек — лента и карта сети

      
Схема цепочек появится после расчёта этапа 1 (пейринг).

      


        

          

            
Лента цепочек — время месяца × цепочки

            

          

          
Строка — цепочка (пейринг), горизонталь — время месяца (UTC). Смена — подложка, рейс — сплошной сегмент, перегон — штриховка, ночёвка — разрыв. Красная полоса сверху — непокрытые рейсы. Карта сети — города и рейсы

            

          

          
Узел — город, дуга — рейсы между городами (толщина — их число), базы выделены цветом акцента. Раскладка силовая, без географии — расстояния и направления условны. Красные дуги — непокрытые рейсы; маршрут выбранной в ленте цепочки подсвечен.

    Доска планирования
    
      
    
        
        
      
    
    
    
    
    
      Как работает этот экран
      
    Готовый ростер как лента «экипаж × дни». Кликните по плитке пейринга,
      чтобы перекинуть его на другого члена экипажа, снять назначение или
      закрепить (pin) — закреплённые защищены от правок. После каждой правки
      законность перепроверяется: пересечения по времени, тип ВС,
      недоступность, покрытие и межпейринговый отдых подсвечиваются.
    
    
    

    
    
      
    
      
    
        
        
        
      
    

      
      
    
        
    Сбой: болезнь / срочная замена
    
        
    
          Отметьте заболевшего — его дни станут жёсткой недоступностью для
          доски и всех проверок. «План ремонта» жадно закрывает сломанные
          пейринги минимальным числом изменений: сначала свободные резервы,
          затем легальные переносы и обмены. План применяется обратимыми
          правками доски; непокрытое честно показывается красным.
        
    
        
    
          События уровня рейсов — отмена, снятие борта, сдвиг — распускают
          пейринги, задевшие эти рейсы. «Пересборка (план Б)» строит
          ремонтный экземпляр: окрестность пересобирается генерацией
          колонок, нетронутые пейринги замораживаются вместе с экипажем
          (пины), новые доназначает солвер. Если часть ног непокрываема в
          узкой окрестности, включается расширение: соседние нетронутые
          пейринги (тот же тип борта, стыковка рядом) размораживаются
          раундами, и колонки строятся заново.

    Балансировка баз
    
      
    
        
        
      
    
    
    
    
    
      Как работает этот экран
      
    Стратегический разрез по экипажным базам: для каждой базы сравнивается
      предложение (линейный экипаж × месячный лимит блок-часов) со спросом
      (блок-часы пейрингов, привязанных к базе), считается утилизация,
      межбазовые связи (прокси дедхедов) и разрез по типам ВС. Из разрыва
      выводится сайзинг: где базе не хватает или избыток экипажа и сколько
      человек перебросить, чтобы выровнять загрузку сети.

    Ask AI — вопросы о программе
    
      
    
    
    
    
      Как работает этот экран
      
    Задайте любой вопрос о работе программы и смежных темах планирования
      экипажей. Можно спрашивать о своих данных: отметьте наборы ниже (или
      просто упомяните их название в вопросе — они подхватятся
      автоматически). Выбор модели честен к контуру: если затронут хотя бы
      один набор с признаком L (только локально), ответ готовит локальная
      модель — вопрос не покидает сервер. Посторонние темы ассистент
      вежливо отклоняет.

    Обучение
    
    
    
    
    
      Как работает этот экран
      
    Интерактивные уроки по разделам программы. Автопилот — программа сама
      проходит сценарий: переключает экраны, подсвечивает элементы и
      рассказывает. Интерактив — вы выполняете шаги сами, программа
      подсказывает и проверяет. Уроки безопасны: они только перемещаются по
      экранам и ничего не отправляют и не запускают.
    
    
    
    
    
  
    

  
  
    
    
    Параметры авиакомпании (уровень 1) — шаблон установки
    
    
    
      Это ШАБЛОН для НОВЫХ наборов. При появлении набора действующие значения
      копируются в него и дальше живут с ним: правка этого шаблона уже
      созданных наборов не касается — иначе один и тот же набор, посчитанный
      в разные месяцы, считался бы по разным нормам без следа в артефакте.
      Правила конкретного набора видны и правятся в таблице «Экземпляры
      задач», столбец «Правила набора». Отпечаток задачи включает правила:
      значения, отличные от встроенных, дают другой отпечаток, и каталоги с
      результатами ведутся отдельно для каждого набора правил.
    
    
    
    
      
    
      
    
        
        
      
    
    
    

    
    Стоимостные параметры (ставки)
    
    
    
      Лёгкая стоимостная модель: оплата за блок-часы, суточные за час вне
      базы, гостиничные ставки по станциям. Используется в карточке
      «Стоимость и гостиницы» и стоимостных показателях. Сохранение —
      только администратор.
    
    
    
    
      
    
        
    
          
          
        
    
        
    
          
          
        
    
        
    
          
          
        
    
        
    
          
          
        
    
      
    
      
    
        
        
      
    
      
    
        
        
      
    
    
    

    
    Параметры оплаты труда (pay-and-credit)
    
    
    
      Контрактные параметры кредитных часов: риги указываются по-отраслевому
      «часов на один кредитный час» (риг служебного времени 1:2 — введите 2).
      Используются в карточке «Оплата и кредитные часы» на вкладке
      «Результаты». Ставка блок-часа берётся из стоимостных параметров выше.
      Сохранение — только администратор.

    ИИ-контур: реестр точек вызова моделей
    
      
    
    
    
    
      Как работает этот экран
      
    Полный перечень мест, где приложение обращается к языковым
      моделям: какой механизм решает «локальная или облачная» и какие
      данные попадают в запрос. Это артефакт для аудита заказчика в
      строгом режиме (облако запрещено для данных заказчика). Реестр
      охраняется автотестом: новая точка вызова без записи здесь роняет
      тесты.

    База шаблонов-исполнителей
    
      
    
    
    
    
      Как работает этот экран
      
    Машинная карта семей шаблонов COSMOS: механика, исполнители,
      признаки сопоставления с правилами пакета и правила действующего
      ВМП, опирающиеся на семью. Шаблон — это код с контрактом и
      тестами, поэтому правка и удаление не редактируют код напрямую:
      кнопки создают заявку контура самоулучшения, изменение проходит
      гейты и принимается человеком. Удаление семьи, на которую
      опираются правила действующего ВМП, — честный отказ с перечнем
      зависимых.

    Студия формализации
    
      
    
    
    
    
      Как работает этот экран

    Установки
    
      
    
    
    
    
      Как работает этот экран
      
    Раздел виден только супер-администратору
      установки. Здесь задаётся API-ключ Claude, извлекается список
      актуальных моделей и назначается модель на каждое использование
      (кодинг, обработка текстов, Ask AI и др.). Облачные модели применяются
      ТОЛЬКО там, где облако уже разрешено контуром данных; данные заказчика
      во внутреннем контуре по-прежнему обрабатывает локальная модель.
    
    
    
    
    
  
    

  
  
    
    
    
      
    Пакеты правил

    Контуры наблюдения
    
      
    
    
    
    
      Как работает этот экран
      
    Каждый контур что-то наблюдает и превращает замеченное в
      предложение об изменении (CR) — сам он ничего не чинит и в рабочие
      настройки не пишет. Четыре контура детерминированы и не вызывают
      языковую модель: «Здоровье данных» (снимки дефектов экземпляров),
      «Отклик планировщика» (повторяющиеся ручные переделки доски с
      указанной причиной), «Надёжность стенда» (укладываемость прогонов в
      бюджет и доля отказов), «Буфер стыковки» (пересадки внутри смены,
      у которых по плану нет запаса времени). Остальные обращаются к
      модели по правилам контура установки. Строка разворачивается в
      подробности; решение по предложениям принимается на вкладке
      «Изменения».

    Изменения (запросы на доработку)
    
      
    
    
    
    
      Как работает этот экран
      
    Единая очередь запросов на изменение (CR). Их формируют агенты
      Автоулучшения: «Отзывы» (кластеры предложений пользователей),
      «Регуляторика» (изменения норм по странам экземпляров), «Идеи UI/UX».
      Приоритет отзывов = число сходных предложений; трудоёмкость 1–10.
      Администратор принимает или отклоняет CR; «Реализовать на Тест»
      запускает агента-исполнителя в изолированном тест-контуре (отдельная
      ветка cr-…, прогон тестов).

      База знаний по выбору решателей
      
      
      
        
        
      
      
    
      
    
      
      Как работает этот экран
      
      «Скилл» — документ с рекомендациями, какие решатели и подходы
      использовать для пейринга и ростеринга. Строится на этапе Test из

      используется как советник — выбор подтверждает человек.
