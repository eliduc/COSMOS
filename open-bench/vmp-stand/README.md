# Стенд искусственных ВМП: чем судят проверки постановки

Проверки постановки (`vmp/formulation_check.py`) отвечают на вопрос половины COSMOS по разделению функций (решение владельца 2026-09-03, `final-report/RAZDELENIE-CDPM-COSMOS-CLD.md`): **даёт ли ВМП корректную задачу пейринга и ростеринга**. Исходные документы авиакомпании им не нужны; соответствие ВМП документам — зона CDPM.

Кто судит сами проверки? Ступени стенда: выдуманные постановки с **заранее написанным приговором**, составленным вместе с материалом и коду проверок не известным. Ступень говорит, ЧТО обязана сказать проверка — класс, уровень, строку и поле, — а не как она это находит. Устройство то же, что у лестницы (`open-bench/ladder/`, теперь зона CDPM): материал выдуман, ответ известен, ни одной модели.

Мир стенда выдуман намеренно: авиакомпания «Ладога-Тест», базы LED и KGD, внебазовый порт ARH, тип судна ЛТ-100, три плановых дня. Ни один инвариант не опирается на набор реальной авиакомпании и на набор «Полярис».

## Ступени

| Ступень | Что в постановке | Что обязана сказать проверка |
|---|---|---|
| **С0** | здоровая постановка: определения, параметры мира, части с а)/б)/в) | «принята», находок нет |
| **С1а** | две жёсткие строки одного вида задают отдых дома 720 и 660 | «постановка противоречива: строка X против строки Y» |
| **С1б** | жёсткая строка 720 и запись файла норм 750 (разные виды) | то же — пара названа |
| **С2** | правила здоровы порознь, но экипаж из 3 при двух пилотах в KGD | проверки постановки принимают; приговор `INFEASIBLE` выносит **решатель** — ступень исполняется отдельным прогоном по отмашке владельца |
| **С3** | база MMK и тип ЛТ-200 объявлены ВМП, в данных их нет; уточнитель «база MMK» | «код из ВМП в данных набора отсутствует» — по каждой строке |
| **С4** | критерий без метрики; метрика пейринга у критерия ростеринга | «критерий без метрики», «метрика не той задачи» |
| **С5** | критерий без ставки; машинный критерий без версии ставок | «ставка не задана», «без версии или даты действия» |
| **С6** | единица нарушения `null`; единица не своей семьи; мягкое без штрафа | «единица размера нарушения не объявлена / не равна единице семьи» |
| **С7** | два критерия на ярусе 1; ярус 2 без допуска; после 2 сразу 4 | «критерии не упорядочены, сравнивать нечем» |
| **С8** | нулевые коэффициенты; предел длительности длиннее горизонта | предупреждения; постановка **принята** |
| **С9** | пакет без формы ВМП | «постановку судить нечем» |

Смысл С0 и всех прочих ступеней один: та же здоровая постановка, в которую внесён ровно один класс порчи. Если проверка находит на ступени что-то сверх приговора, виновата проверка (ложная тревога), а не ступень.

## Как запустить

```
python open-bench/vmp-stand/evaluate_stand.py                 # ступени из памяти
python open-bench/vmp-stand/build_stand.py --out <каталог>     # ступени файлами
python open-bench/vmp-stand/evaluate_stand.py <каталог>        # оценка по файлам
python -m vmp.formulation_check <каталог>/С3                  # вердикт одной ступени
```

Оценщик возвращает ноль, когда на каждой ступени вердикт совпал и находки совпали с приговором как мультимножество: ни лишней, ни недостающей. Тот же прогон закреплён проверками `tests/vmp/test_vmp_stand.py`, поэтому изменение проверок обязано ронять набор, а не обнаруживаться на живом пакете.

## Правило пополнения

Каждый класс негодной постановки, найденный где угодно — на живом пакете, в аудите, у решателя, — прежде лечения становится ступенью стенда с приговором. Лечение формулируется как свойство постановки задачи вообще и проверяется вопросом: **сказано ли это без упоминания конкретного набора данных?** Правка, которую нельзя так сформулировать, есть заплатка и в стенд не принимается.

Проверки ничего не чинят: негодная постановка возвращается с названием строки и поля. Пустая допустимость в полном смысле (правила совместны порознь, но решений нет) проверками не ловится по построению — это ступень решателя.
