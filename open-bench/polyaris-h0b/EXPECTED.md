# ИДАК H0-B — ожидаемое поведение конвейера (вариант B)

Поручение владельца 09.09.2026: «Н0-0.5 — вариант B — когда есть
шаблон с двумя параметрами, один параметр есть, второго в правилах нет,
делается запрос а/к в анкете, после подачи ответов на анкету, всё
садится на шаблон».

## Состав набора

| Файл | Что внутри | Отличие от H0 |
|---|---|---|
| docs/ID-H0B-VMP-1.docx | заголовок, общий раздел, часть 1 а/б | только имя заказчика в шапке |
| docs/ID-H0B-VMP-2.xlsx | часть 2 а/б | НЕТ строки VN-024 «Отдых вне базы»; строки ниже поднялись на одну |

| etalon/ANSWER-BOOK-MACHINE.json | ответы авиакомпании | вопрос о параметре → «10:00 (600 минут)»; история → «б» |

Сборка: `python open-bench/polyaris-h0b/build_kit_h0b.py` (сборщик H0
поверх формы H0; самопроверка требует совпадения якорей с H0 со сдвигом
строк листа «VMP-H0-2» ниже снятой на одну).

## Что должен сделать CDPM

1. Заморозка, извлечение — как на H0: 15 правил документами. Правило
   VN-023 «Отдых дома» садится на семью `rest_floors` (категория A);
   у семьи два параметра — `min_rest_home` (задан, 720) и
   `min_rest_outstation` (документами не задан).
2. Обработчик обязан задать вопрос анкеты о недостающем параметре
   (закон полноты: второй параметр семьи не подразумевается нулём и не
   выводится из первого). Id вопроса — по соглашению CDPM; предложение
   COSMOS: `Q-3b-параметр-rest_floors-min_rest_outstation`. Книга ответов
   ловит его точно и по префиксу семьи `Q-3b-параметр-rest_floors`
   (общий префикс `Q-3b-параметр-` снят 09.09.2026 по замечанию CDPM:
   он отвечал бы текстом про отдых на вопросы о параметрах чужих семей).
3. Ответ авиакомпании: «Минимальный отдых между сменами вне базы —
   10:00 (600 минут)». Закон CDPM «полнота параметров семьи» (09.09.2026):
   ответ применяется как второй параметр в посадку семьи у
   правила-носителя VN-023 (цитата = ответ, признак «по ответу анкеты» =
   вопрос); отдельного правила VN-024 в ВМП нет. Эталон `VMP-H0B.json`:
   15 правил, VN-023 с обоими параметрами. «Буква в букву» с H0 — по
   машинному содержанию семьи `rest_floors` (720 и 600), не по числу
   правил-носителей.
4. Вопрос линии данных об истории (1.17.2) — «б», как у H0-К.
5. Готовность пакета «в», целевых две; ступень лестницы готовности по каждой задаче — по
   ЕДИНСТВЕННОМУ источнику `kit-manifest.json` →
   `expect.readiness_ladder`; здесь она НЕ дублируется (16.09.2026:
   два источника разошлись — манифест обещал одну ступень, этот
   текст называл другую; слово владельца — свести к одному
   источнику, значение при этом не подгонялось).

## Что должен сделать COSMOS

Прогон пакета как у H0: пейринг «построен», ИДАК 9/0; ростер «допустимо»,
ИДАК 12/0 (по чтению каналом api). Строки VN-023 и VN-024 сверки ИДАК —
оба пола отдыха, второй — из ответа.

## Что считается дефектом

- вопрос о параметре не задан, а пакет собран с одним полом отдыха;
- вопрос задан не о том (не о `min_rest_outstation` семьи `rest_floors`);
- после ответа ВМП не эквивалентна эталону (ответ не сел на шаблон);
- любой вопрос сверх перечня `expect.questions`.
