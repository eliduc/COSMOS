# ИДАК H0-К — ожидаемое поведение конвейера

Поручение владельца 04.09.2026: «ИДАК H0-К — то же самое, что H0, но в
нём отсутствует критерий оптимизации. При прогоне должно быть сообщение
о том, что критерия оптимизации нет и что возможен только поиск
feasibility-soft — оптимальное решение, удовлетворяющее всем жёстким
ограничениям, с критерием оптимизации, равным взвешенной сумме
штрафов».

## Состав набора

| Файл | Что внутри | Отличие от H0 |
|---|---|---|
| docs/ID-H0K-VMP-1.docx | заголовок, общий раздел, часть 1 а/б | только имя заказчика в шапке |
| docs/ID-H0K-VMP-2.xlsx | часть 2 а/б | нет |
| docs/ID-H0K-VMP-3.jpg | разделы «в) критерии оптимизации» обеих частей | пусты: под заголовком «(нет)» |
| data/ID-H0-DATA.xlsx | книга данных | та же, что у H0 |
| etalon/VMP-H0K.json | эталон ВМП: 16 правил H0 буква в букву | objectives = [] |
| etalon/ANSWER-BOOK-MACHINE.json | ответы авиакомпании | Q-3a-GOAL, Q-3b-GOAL → «критерия оптимизации нет…» |
| kit-manifest.json | манифест | strict_questions=false, ключ expect |

Сборка: `python open-bench/polyaris-h0k/build_kit_h0k.py` (сборщик H0
поверх формы H0; самопроверка требует совпадения якорей правил с H0).

Тот же запуск перевязывает набор **ИД H0-КИ**
(`open-bench/polyaris-h0kh` — H0-К с листами истории): своего сборщика
комплекта у него нет, и документы правил, обе проекции эталона (с
отпечатками по факту файлов набора), карта якорей, строки jpg и книга
ответов переносятся сборщиком, а не рукой (11.09.2026; прежде переносили
рукой, и ВМП эталона Н0-КИ оставался с отпечатками прежней сборки).
Оттуда же приходят ожидания обоих вариантов книги истории — stop и full:
вердикты стадий и слово непротиворечивости. Своё у Н0-КИ — книга данных
(`build_data_h0kh.py`) и ожидания истории в манифестах вариантов; их
перенос не трогает.

## Что должен сделать CDPM

1. Заморозка, извлечение, цикл — как на H0: 16 правил, целевых нет.
   Обработчик обязан задать вопросы о целевой обеих частей (Q-3a-GOAL,
   Q-3b-GOAL) с текстом «В документах не обнаружено целевой функции …
   (критерия оптимизации) … Либо явно подтвердите, что критерия
   оптимизации нет … — тогда режим optimization недоступен: решение
   ищется в режиме взвешенных штрафов (feasibility-soft) …».
   Других вопросов быть не должно (книга ответов иных вопросов не
   закрывает — несопоставленный вопрос останавливает раннер).
2. Стадия answers: книга отвечает «Критерия оптимизации нет…», обработчик
   ответов выставляет decline=true, objectives пусты; ответы применены.
3. Матрица корректности обеих задач: feasibility-hard и feasibility-soft
   готовы, optimization — состояние «отказ подтверждён» с сообщением
   `cdpm.model._NO_CRITERION_NOTE`:
   «критерия оптимизации нет (подтверждено авиакомпанией): режим
   optimization недоступен; возможен только поиск feasibility-soft —
   оптимальное решение, удовлетворяющее всем жёстким ограничениям, с
   критерием, равным взвешенной сумме штрафов мягких правил (без
   взвешенных мягких правил — feasibility-hard, любое допустимое)».
4. Пакет постановки (спецификация 1.14 + kit): allowed_modes обеих задач
   = [feasibility-soft, feasibility-hard]; objectives пусты, objective.json
   без критерия пейринга; лестница готовности readiness_matrix.columns.*:
   state = feasible_soft, grounds.criterion.defined = false, notes содержит
   сообщение выше. Гейт пакета чист.

Гейты эквивалентности по стадиям: extract и cycle показывают два
«открытый вопрос анкеты» (GOAL обеих частей) — это по замыслу набора;
answers и package обязаны быть EQUIVALENT (правила 16/16, целевых 0/0,
форма полная), плюс «ОЖИДАНИЯ НАБОРА выполнены» (ключ expect манифеста;
расхождение перекрашивает вердикт в EXPECT_MISMATCH).

## Что должен сделать COSMOS

Страница «Пакет постановки» → кнопка без явного режима: шаг Ш-1к «режим
задачи» читает allowed_modes без optimization и сообщает, что критерия
оптимизации в пакете нет и возможен только поиск feasibility-soft (все
жёсткие выполнены, целевая — взвешенная сумма штрафов мягких правил,
решение оптимально по ней); режим и пояснение — в выдаче обеих задач
(mode, mode_note) и в строке «Режим» состояния страницы; текст CDPM —
в readiness_matrix.columns.<task>.notes пакета. Расчёт идёт, не
останавливается; сертификат и выдача — как у H0 в режиме feasibility-soft.

## Прогон

```bash
python open-bench/polyaris-h0/run_local_pipeline.py --kit-dir open-bench/polyaris-h0k --out <каталог> --until package
```

Прогон — с моделями (раскладка H0: agents-layout-h0.json), только по
отмашке владельца; затем пакет — на ручки COSMOS (tools/certify_button.py
--cosmos-url …) без mode.
