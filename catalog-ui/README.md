# Интерфейс каталога шаблонов (`catalog-ui`)

Пять экранов службы каталога (`catalog_service`, порт 8105): записи
(семьи и критерии), словари, заявки, исполнители по продуктам, версии и
выпуски. Стек и внешний вид — как у панели CDPM (`cdpm-ui`): Vite +
React + TypeScript, Tailwind на токенах темы `--cf-*`, компоненты
`Button`, `Modal`, `ConfirmDialog`, `StatusBadge`, `CommandPalette`,
`ThemeToggle`, `TooltipLayer`, тосты `react-hot-toast`.

Служба раздаёт собранную статику по `/ui/`, поэтому маршруты живут в
хеше (`HashRouter`): адрес экрана — `<CREW_CATALOG_URL>/ui/#/…`
(контракт адресов — `catalog_service/API-CONTRACT.md` §6).

## Сборка

```
cd catalog-ui
npm install
npm run build      # tsc -b && vite build && node scripts/stamp.mjs
npm run lint       # oxlint (dist в проверку не входит)
npm run dev        # dev-сервер Vite, /api проксируется на 127.0.0.1:8105
```

`dist/` **коммитится вместе с `src/`**: установка COSMOS у заказчика не
требует Node (решение владельца, вариант А). Гейт `T12`
(`tests/catalog_service/test_ui_static.py`) не даёт сборке отстать от
исходника.

## Штамп свежести `dist/build-stamp.json`

`{"form_version": 1, "files": N, "src_sha256": "<64 hex>"}` — отпечаток
исходных файлов интерфейса. Формула одна на три места
(`scripts/stamp.mjs`, гейт T12, `catalog_service/API-CONTRACT.md` §7):

* входы: `src/**`, `index.html`, `public/**`, `package.json`,
  `package-lock.json`, `vite.config.ts`, `tsconfig*.json`,
  `tailwind.config.js`, `postcss.config.js`, `.oxlintrc.json`;
* пути — относительные от `catalog-ui/`, в POSIX-форме, отсортированы;
* содержимое — байты файла с заменой `\r\n` на `\n` (клон на Windows и
  на Linux даёт один штамп; за перевод строк отвечает `.gitattributes`);
* вклад файла — `<путь>\0<содержимое>\0`;
* штамп — sha256 конкатенации вкладов в порядке путей.

Правило простое: **правил `src/` — пересобери `dist/` и закоммить их
вместе**.

## Словарь подписей

Все слова экранов живут в `src/i18n/ru.ts`; в файлах `src/**/*.tsx`
русских строк нет вовсе — гейт `T13`
(`tests/catalog_service/test_ui_i18n.py`) краснеет на первой же. Экраны
зовут `t('ключ')` и `tf('ключ', {подстановки})`; тип `MessageKey` не
даёт назвать ключ, которого в словаре нет.

Гейт T13 проверяет четыре вещи: кириллицы в `*.tsx` нет; каждый ключ
вызова есть в словаре; мёртвых ключей в словаре нет; подпись с
подстановками `{имя}` показывается только через `tf()`.

Содержимое записей каталога (заголовки семей, семантика, слова-носители,
состояния «есть»/«заявлен»/«нет», слова отказов службы) — данные, а не
подписи: они приходят от службы и не переводятся. Слова каталога, по
которым интерфейс принимает решения (роли, состояния, статусы), собраны
в `src/api.ts` — `ACTOR_OWNER`, `STATE_PRESENT`, `REQUEST_ACCEPTED` и
рядом.

Пять языков экрана — по отдельному слову владельца: тогда рядом с
`ru.ts` появляются `en/uz/kk/ar.ts`, паритетный тест ключей и
подстановок и `dir="rtl"` для арабского.

## Раскладка

```
src/api.ts                  клиент службы: формы ответов, коды отказов
                            (ServiceError), слова каталога, карта цветов
src/i18n/{index,ru}.ts      словарь подписей и t()/tf()
src/stores/                 сеанс и кэш словарей, тема, оболочка
src/components/common/      примитивы панели (кнопка, окно, чип, тосты)
src/components/catalog/     карточка записи, параметры, стенд, история,
                            замечания, «что изменилось», клетка
                            исполнителя, чип состояния, поле JSON
src/pages/                  пять экранов и карточки
scripts/stamp.mjs           штамп свежести сборки
```

## Как проверить руками

```
.venv\Scripts\python.exe -m catalog_service --port 8105 --actor owner
```

(с копией каталога: `CREW_TEMPLATE_CATALOG` — на копию,
`CATALOG_WORK_DIR` — на временную папку; живой `catalog/` репозитория
для проб не нужен). Дальше — `http://127.0.0.1:8105/ui/`:

1. строка состояния сверху: версия и отпечаток каталога, «черновик» или
   «выпуск», рабочее место (владелец/аналитик) либо «режим просмотра»,
   счётчики черновиков и открытых заявок;
2. «Семьи и критерии»: список с фильтрами из словарей, карточка записи
   со всеми полями схемы, «Сохранить черновик» (заметка обязательна) →
   отпечаток каталога НЕ меняется. Поля каталога 0.5.0 у семьи:
   «Свидетель природы» рядом с природой, «Размер нарушения» рядом с
   единицей нарушения, группа «Чтение истории» (вид из словаря
   `history_read_kinds`; вид снят — поле становится `null` целиком, а не
   полупустым объектом). Единица нарушения выбирается кодом со словом
   каталога рядом: `night — ночь`;
3. «Словари»: перечень ключей, правка значений, служебные перечни —
   неактивны со словами; словарь-карта (`violation_units`) сверх поля
   JSON показан таблицей «Код — слово»;
4. «Заявки»: подача, решение владельца со словами, «Перевести в записи»;
5. «Исполнители по продуктам»: карточки файлов привязок, свежесть,
   матрица «запись × вид × продукт», раскрытие клетки;
6. «Версии и выпуски»: сборка черновика (в ответе — три команды
   перегенерации привязок), сравнение версий, выпуск владельцем,
   выгрузка и загрузка одним файлом.

В режиме просмотра (`--read-only`) кнопки записи видны, но неактивны, и
подсказка называет причину словами службы.

## Права и подписи

Кнопки записи гасятся по карте прав службы (`GET /api/session` →
`rights[<операция>]`), а подсказка неактивной кнопки несёт слова отказа
САМОЙ СЛУЖБЫ (`rights[…].words`). Копий этих слов в словаре подписей
`src/i18n/ru.ts` нет намеренно: второе вычисление прав разошлось бы со
службой при первой же правке её текстов.

## Что осталось на шаг 5б (названо честно)

* «Словари»: объект (`check_templates`, `unbound_params`, `world_forms`,
  `synthetic_codes`) правится целиком как JSON, а не таблицей подключей
  по схеме (§4.2 проекта). Правка возможна и честна — служба судит
  форму и отвечает адресами, — но таблицы подключей ещё нет. Со словарём
  `violation_units` (с каталога 0.5.0 — карта «код → слово») закрыта
  только половина: таблица «Код — слово» ПОКАЗЫВАЕТСЯ рядом с полем
  JSON, а правится ключ по-прежнему целиком.
* «Семьи и критерии»: колонка «стенд» списка показывает ЧИСЛО стендовых
  задач записи (так её отдаёт `GET /api/records`), а не счётчики
  исходов; исходы видны в карточке записи и на экране «Исполнители по
  продуктам». Расхождение §4.1 и §3 проекта закреплено в контракте
  (`catalog_service/API-CONTRACT.md`, `GET /api/records`).
